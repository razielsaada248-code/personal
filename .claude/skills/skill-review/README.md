# בודק הסקילים

סקיל שבודק סקיל של מישהו אחר לפני שהוא נכנס אליך: ביטחון, איכות, התאמה למשימה אמיתית, עדכונים והידלקות. מחזיר דוח שנפתח בשורה אחת: להתקין, לא להתקין, או לתקן קודם.

## התקנה, בשיחה עם קלוד

באפליקציה של קלוד, בלשונית Code: Local, ואז Select folder, ובוחרים את התיקייה שבה שמרת את הקובץ שהורדת. ואז כותבים:

> פרוס את קובץ ה-zip שבתיקייה הזאת והתקן את הסקיל skill-review בתיקיית המערכת שלי, כסקיל כללי שזמין לי בכל מקום. אחר כך תראה לי איפה הוא יושב.

הנתיב שהוא מראה צריך להתחיל ב-‎~/.claude, לא בתיקיית פרויקט.

## איך משתמשים

שומרים את הסקיל שרוצים לבדוק בתיקייה כלשהי, ואומרים:

> תעביר את הסקיל שבתיקייה הזאת דרך סקיל הביקורת, ותן לי את פסק הדין

הדוח נפתח בשורה אחת. דגל אדום בשלב הביטחון: לא מתקינים, גם אם הסקיל נראה שימושי.

## מה הוא בודק בשלב הביטחון

ארבע בדיקות, על כל קובץ בחבילה ולא רק על SKILL.md:

1. האם משהו בסקיל יוצא לאינטרנט, ולאן.
2. האם הוא נוגע בסודות: סיסמאות, מפתחות, `.env`, `~/.ssh`.
3. האם יש בו הוראות חבויות, כמו "התעלם מהוראות קודמות", טקסט מוסתר או הוראה שנטענת מהרשת בזמן ריצה.
4. בונוס: מי כתב אותו, ומה המוניטין של המאגר.

## הכללים

סקיל נכנס כשמשימה אמיתית וחוזרת דורשת אותו. "אולי יעזור מתישהו" הוא עומס, לא יכולת.

וסקיל שעבר בדיקה הוא סקיל שגרסה אחת שלו עברה בדיקה. לכן הבודק מכבה את העדכון האוטומטי, שומר את הגרסה שנבדקה, וכשמגיע עדכון קורא את ההפרש מחדש. מעדכנים כשאתם רוצים, לא כשהסקיל רוצה.
